# NotesApp architecture review

Reviewed on 2026-09-11 against commit `107b36a`.

Scope: `/home/bkhanale/workspace/bkhanale/notesapp` at commit `107b36a`, read only.
Uncommitted work in `docs/plans/004-remaining-work.md` and
`apps/web/src/features/shortcuts.tsx` is ignored.

## Verdict

**Yes. This is industry standard architecture, and it is above the usual bar
for a 0.1.** The single most important reason: the boundaries are not a
convention that a reviewer has to police, they are executable. The contract in
`packages/api-contract/openapi.yaml` creates every route, and
`apps/server/src/http/register.ts:455-532` validates both the request and the
response against that contract at run time and refuses to send an answer that
leaves it. `tools/check-boundaries.mjs` parses every source file and fails
`pnpm lint` on a forbidden import, a deep import, a handwritten `fetch`, or an
undeclared dependency. `packages/core/package.json` declares zero runtime
dependencies, so the domain layer cannot reach transport, SQL, or React even by
accident. Three separate database roles plus `FORCE ROW LEVEL SECURITY` on
every table mean the tenancy rule holds even if a handler forgets it. Very few
codebases of this size enforce their own design this way.

The backend is the stronger half. The web application is good but has one real
architectural smell (a module global editor bus) and two very large modules.
There is exactly one finding I would block a 0.1 on, and it is a two hour fix.

## P0 candidates

Only one finding here clears the bar of "a senior reviewer blocks the 0.1".

### P0-1. The password reset token is written to the application log

**What.** `apps/server/src/auth/better-auth.ts:69` serves
`GET /api/auth/reset-password/:token` as a browser navigation route. The
`onResponse` hook logs every request URL at `info`
(`apps/server/src/request-log.ts:50-57`), and `redactUrl`
(`request-log.ts:20-28`) removes only the query string. Path segments pass
through verbatim. The Fastify request serializer does the same
(`apps/server/src/app.ts:133`). A live, single use, one hour, full account
takeover token therefore lands in the container log on every reset.

**Why it is P0.** It is a credential in a log. It contradicts the module's own
docstring at `request-log.ts:3-5` ("passwords, tokens and cookies never reach a
log record") and the explicit rule in `apps/server/AGENTS.md` ("No rejected
body, token, or password in a log line"). Logs get shipped, tailed in a support
session, and pasted into issues. In a codebase whose whole premise is that
stated invariants are enforced, an invariant that is documented, relied on, and
false is exactly the class of defect that blocks a release.

**Fix.** Redact the trailing segment of any path under
`/api/auth/reset-password/`, ideally by redacting every path segment that is
not part of a known route template. Add a unit test on `redactUrl` and an
integration test that drives the reset link and asserts the log record carries
no token.

**Effort: 2 hours.**

## Better than typical, keep these

1. **Executable boundaries.** `tools/check-boundaries.mjs` is a real AST walker
   with a per package allow list, a browser safety set, a transport ban, a deep
   import ban, a declared dependency check, and a test placement rule, and it
   has 639 lines of its own tests. Most teams write this rule in a README and
   then break it in month two.
2. **Two way contract enforcement at run time.** Validating the response
   against the declared schema and refusing to send a mismatch
   (`register.ts:505-532`) is rare and it is the reason the generated client can
   be trusted.
3. **The `Actor` brand.** A `unique symbol` that only `verifyActor` can mint,
   not exported from the package entry, with a compile time negative fixture
   (`packages/core/src/identity/actor.ts:39-54`, `tools/actor-brand/fixture.ts`).
   Authorization cannot be forged by a caller.
4. **Three layer authorization.** Handler grant check, then core `authorize()`
   as the intersection of role and verified grant, then `FORCE ROW LEVEL
SECURITY` in the database keyed on the transaction local `notesapp.account_id`.
   Any one layer can be forgotten without a data leak.
5. **Three least privilege roles.** A migration role, a runtime role that is
   append only on the content tables, and a separate identity role that is the
   only role with rights on the four Better Auth tables. Session tokens and
   password hashes are unreachable from an application query whatever identity
   it sets.
6. **Redaction by omission, not by list.** The Fastify request serializer is
   replaced so headers cannot be logged at all (`app.ts:112-141`), and the
   PostgreSQL error is reduced to four safe fields because `detail` echoes the
   offending value (`workspace-store.ts:191-196`).
7. **Idempotency done properly.** An actor bound mutation receipt with a
   request digest, read before the heads and before the quota, replaying the
   stored outcome including the superseded heads
   (`commit.ts:342-348`, `workspace-store.ts:1906-1916`).
8. **The commit and rebase rules.** `packages/core/src/files/commit.ts` states
   its transaction order in the header, explains every refusal, and never
   crosses a deletion boundary in either direction. 1094 lines of tests back it.
9. **Contrast is tested for every theme, not asserted.**
   `packages/ui/src/theme.test.ts:99-145`.
10. **`AGENTS.md` per directory, generated from `rules/` and checked.**
    `tools/check-agents-md.mjs` verifies the root file matches what `rules/`
    composes and that every code owning directory has one under 80 lines. The
    16 decision records carry the reasoning the code cannot.
11. **Zero lint suppressions and a very strict compiler.** No
    `@ts-expect-error`, no `@ts-ignore`, no disable comment anywhere, with
    `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, and
    `skipLibCheck: false` as the baseline.
12. **Image inspection in an isolated child process** with a timeout, a pixel
    cap, an animated frame bomb guard, and a declared versus sniffed type
    mismatch reject (`apps/server/src/jobs/inspect-image-worker.ts:57-112`).
13. **A hash based CSP with no `unsafe-inline` for scripts**, recomputed from
    the served bytes and cached by mtime
    (`http/security-headers.ts:46-64`, `:151-161`).
14. **The sandboxed diagram frame**, built as one self contained inline bundle
    precisely so it needs no network, running in an opaque origin with
    `connect-src 'none'` and bounded message payloads
    (`vite.config.ts:165-228`, `apps/web/src/diagram/frame.ts:127-159,257`).
15. **CI that pins every action by commit SHA**, times out every job, runs a
    four way browser matrix, and enforces a 250 KiB gzipped initial JavaScript
    budget and a service performance budget as their own jobs.
