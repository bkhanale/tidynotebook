# Release 0.2.0

Status: active

This is the single prioritized list for the 0.2.0 release, and no other
document holds a competing list.

The living list of what 0.2.0 ships. Every section is sorted by impact,
highest first, and that order is the owner's priority order, not an identifier
order, so the top row of a section is always the next thing to do in it.

0.2.0 opens after the 0.1.0 tag. Every row names the decision record or the
design that holds it, and the file that proves the state. Update this file in
the same change that closes a row. [The 0.1.0 list](0.1.0.md) is closed, and it
holds what that release shipped and what it carried on purpose.

Status values: `open`, `partial` (the code changed but the proof or a part is
missing), `accepted` (a decision was made to carry it).

The portable Markdown epic has five steps. Each step keeps `pnpm verify`
green, and each one updates the nested `AGENTS.md` of the directory it changes
in the same change.

1. An image becomes a file with a relative path: the insertion in
   `apps/web/src/features/note-editor.tsx` names the stored path of the
   attachment under one `attachments/` folder at the workspace root. 6 hours.
2. A note link is a relative `.md` path: `classifyUrl` in
   `packages/markdown/src/policy.ts` accepts a relative path and refuses one
   that leaves the tree, and the renderer, the live preview and
   `resolveLinkAction` resolve it against the path of the open note. 6 hours.
3. The link index stores a target path, and a rename or a move rewrites every
   inbound relative link in the same changeset
   (`packages/core/src/files/operations.ts`). Backlinks land here. 10 hours.
4. Export copies the tree with no reference rewrite, and import reads a folder
   of `.md` files and images into the tree
   ([decision 0009](../decisions/0009-export-first-import-later.md)). 8 hours.
5. A migration step rewrites the 0.1.0 content from `/attachments/<id>` and
   `/notes/<id>` to relative paths, and reports each reference that resolves
   to nothing. 4 hours.

The publish row needs a design in `docs/design/` before any code, because it
adds the first path that serves a person with no account. The owner's
direction for it: one read-only link for a note or for a folder, an optional
password on the link, no reader account, and the same sanitized renderer that
Read mode uses
([decision 0003](../decisions/0003-read-mode-uses-the-shared-renderer.md)).
The link is publication and not collaboration: a reader never writes.
