# Release 0.1.0

Status: complete

This is the single prioritized list for the 0.1.0 release, and no other
document holds a competing list.

This list is closed. It holds what 0.1.0 shipped and what it carried, and
[the 0.2.0 list](0.2.0.md) holds every row that is still open. Each section
keeps the owner's priority order, highest impact first.

Audited against `c91c717` on 2026-09-11, and extended by the
[architecture review](../audits/2026-09-11/architecture-review.md) of the same
day. Every row names the audit id from
[the v0.1 revamp plan](../plans/003-v0.1-revamp.md) section 4, or a plain name when the
audit holds no id, and the file that proves the state. Update this file in the
same change that closes a row.

Status values: `open`, `partial` (the code changed but the proof or a part is
missing), `accepted` (a decision was made to carry it).

## 1. Before the 0.1.0 tag

No open row blocks the tag. BE-27, the rate limit on the setup and the
authentication routes, moved to section 2 of [the 0.2.0 list](0.2.0.md) with
the security and deployment work.

One surface is closed. `apps/web/src/features/editor/note-editor.tsx` is the
one live surface that reads and writes a note; Read mode, the Write and Read
toggle, and the `Cmd or Ctrl + Shift + P` switch are gone, and
`note-read-mode.tsx` is deleted. `packages/editor/src/widgets.ts` hides the
code fence lines, which closes MD-25 and QA-25, and
`packages/editor/src/editor-theme.ts` gives a heading more space above than
below. `tests/e2e/note-surface.spec.ts` reads a note on the one surface and
`packages/editor/src/widgets.test.ts` proves the hidden fences.
[Decision 0025](../decisions/0025-the-live-preview-is-the-one-note-surface.md)
supersedes decision 0003, and it follows
[design 006](../design/006-the-one-markdown-surface.md) and
[plan 005](../plans/005-the-one-markdown-surface.md).

Recent is closed. `apps/web/src/shell/shell.tsx` shows the open note in the
tree only: it opens the folders of the open note through `openFolder` and
scrolls the active row into view, so a note no longer appears twice.
`ancestorFolders` in `apps/web/src/lib/note-list.ts` states which folders
to open, `apps/web/src/lib/note-list.test.ts` proves it, and
`tests/e2e/open-note-reveal.spec.ts` drives the reveal from the palette.

Sidebar delete is closed. `apps/web/src/shell/shell.tsx` offers Delete on
the note row and on the folder row, and
`apps/web/src/features/editor/note-delete.ts` writes a tombstone checkpoint
for each note as the note screen does, while the open note goes through the
delete of the note screen. `tests/e2e/sidebar-delete.spec.ts` drives Delete
from both rows.

Mode parity retired with Read mode. The one-surface work above removed the
second surface, so the parity item and its spec are gone. The one surface reads
note typography from `packages/editor/src/editor-theme.ts` through the central
variables in `apps/web/src/tailwind.css`, and a table stays editable text under
[decision 0002](../decisions/0002-widgets-only-where-text-cannot-express.md).

The structure epic is closed. Its five steps moved the tree to the shape of
decision 0018, and each step updated the nested `AGENTS.md` of the directory it
moved and `tools/check-boundaries.mjs` in the same change, so the checker holds
the new shape.

1. `packages/storage-browser/src/local-store/` splits the store by area behind
   the same port. https://github.com/bkhanale/notesapp/issues/6
2. `apps/web/src/shell/shell.tsx` holds the layout frame, the two route views
   are their own files, and `apps/web/src/features/editor/` splits the editor
   into the host, the attachment URL owner and the read mode renderer.
   https://github.com/bkhanale/notesapp/issues/7
3. `apps/server/src/plugins/` and `apps/server/src/routes/` replace
   `apps/server/src/http/`. https://github.com/bkhanale/notesapp/issues/8
4. `packages/storage-server/src/workspace-store/` holds one repository per
   context plus `transaction.ts`. https://github.com/bkhanale/notesapp/issues/9
5. `apps/web/src/features/<feature>/`, `apps/web/src/shell/`, and
   `apps/web/src/lib/` replace the flat feature directory.
   https://github.com/bkhanale/notesapp/issues/10

## 3. Correctness and product gaps

The eight open rows of this section moved to section 3 of
[the 0.2.0 list](0.2.0.md). They are the keystroke cost, BE-09, the diff worker
chunk, the binary source file, the welcome note, the contract file split, the
type assertions, and ENG-13. None of them blocks the tag, and each one keeps
its GitHub issue in the 0.2.0 milestone.

The purge resurrection is closed. A permanently deleted note came back,
because the local reconciliation kept traces of a purged file. `forgetFileRows`
in `packages/storage-browser/src/local-store/shared.ts` now removes the accepted
row, the drafts, the checkpoints, the queued mutations, and the recovery copies
of one file. A `purged` refusal forgets the file instead of parking its text
(`packages/sync/src/queue.ts`), a full snapshot forgets a file it leaves out
that has no queued work, and an accepted tombstone drops its deletion draft. The
audit of [2026-09-12](../audits/2026-09-12/save-delete-trash.md) states the
faults F1, F3, F4, and F5 that this closes. Regression tests are in
`packages/sync/src/engine.test.ts` and
`tests/integration/browser-storage.test.ts`. Fault F2, the un-delete on a
concurrent stale head, is carried to [the 0.2.0 list](0.2.0.md), where epic B of
[plan 004](../plans/004-streamline-save-and-delete.md) closes it with the
last-writer-wins model.

## 5. Accepted debt

These are carried on purpose. They do not block a release.

The content that 0.1.0 writes holds `/attachments/<id>` and `/notes/<id>`
references, and the portable Markdown epic of
[the 0.2.0 list](0.2.0.md) rewrites it.

| Id                     | Item                                   | Why it is carried                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| QA-28                  | The browser suite is stale             | The suite names labels and screens that the product no longer has. `grep -rn "Save this note\|Create a new note\|Backlinks\|Personal\|Switch to\|History and checkpoints\|Search note content\|Open note" tests/e2e` finds 33 hits in every spec and in `support/account.ts`, and `first-user.spec.ts` starts from an empty workspace that now holds the welcome note. Browser testing happens at the very end, after a few more features, and it is done holistically, so the suite is rewritten once                                                           |
| ENG-10, ENG-17, ENG-18 | The thorough browser matrix            | Same reason. The owner wants the browser suite built once the feature surface settles, so it is the last block of work before a wider release, not a gate for 0.1.0                                                                                                                                                                                                                                                                                                                                                                                              |
| Portable references    | The note text is not portable Markdown | A pasted image is stored as `![name](/attachments/<revision-id>)` (`apps/web/src/features/note-editor.tsx:857`) and a note link can be `/notes/<file-id>` (`packages/markdown/src/links.ts`). Export writes the image bytes to `attachments/<revision-id>.<ext>` (`apps/server/src/http/export.ts:137`) and does not rewrite the text, so an exported image is a dead link. [Decision 0021](../decisions/0021-portable-markdown-at-rest.md) makes the stored text portable and rewrites the 0.1.0 content in [the 0.2.0 list](0.2.0.md), so 0.1.0 ships as it is |
| ENG-01                 | The CI matrix on GitHub                | GitHub CI has no credits, so `ci.yml` stays disabled and every check runs on the owner's machine. The only workflow that is allowed on GitHub Actions is a release workflow that builds the GHCR image on a tag, and `.github/workflows/release.yml` does that                                                                                                                                                                                                                                                                                                   |

ENG-25, the toolchain guide split, is closed. `docs/development/toolchain.md`
now holds the durable policy only, the per task evidence is gone, and the
boundary rules sit in that page and in `docs/development/architecture.md`
rather than in a separate guide. `docs/README.md` states the rule that keeps
them that way, and `tools/check-docs.mjs` enforces it.

Because the CI workflow is off, "green in CI" in
[the plan](../plans/003-v0.1-revamp.md) section 8 is read as "green on the local
machine". `pnpm verify` passes on this change with 821 unit
tests and 229 integration tests.

The initial JavaScript budget is no longer carried. The initial route measures
160,298 gzip bytes against the 256,000 byte budget, and
`tools/performance/bundle-budget.mjs` passes.
