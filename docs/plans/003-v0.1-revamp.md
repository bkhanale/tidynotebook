# NotesApp v0.1 revamp plan

Status: approved, 2026-09-10. Baseline commit `40eebba`.

This document defines what NotesApp v0.1 is, the architecture decisions that
get it there, and every change item grouped into workstreams and phases. Five
audit reports in `docs/plans/003-audit/` hold the evidence. Item IDs in this
document (MD, UI, BE, ENG, QA) point to rows in those reports.

## 1. Why we are stuck

The code base is large and carefully built, but it was built for a different
product: a multi-user, multi-workspace, collaborative notes service with
sharing, invitations, conflict branches, agent tokens, remote MCP and OAuth.
The product was then simplified to one user and one explicit Save model, but
most of the old structure stayed. Each round of "improvements" polishes one
surface while the next surface still reflects the old product. That is the
loop.

The audit found the same pattern at every layer:

- Two Markdown engines. The screen the user types in is driven by a regular
  expression scanner in `packages/editor`. The correct remark renderer in
  `packages/markdown` has no consumer at all. They already disagree on escapes,
  footnotes, autolinks, setext headings, thematic breaks and code fences.
- An explicit Save model with no visible save state. Nothing on screen tells
  the user whether their work is saved.
- Basic notes-app capabilities are missing (trash, export, sort by recency,
  created date, find in note, bold and italic shortcuts) while operator
  features are shipped as screens (purge with raw UUIDs, recovery, offline
  status, agent tokens, workspace roles).
- The save path can lose content silently in ordinary single-user situations
  (stale draft shadows newer content, stale delete removes newer edits, a
  refused save is parked in IndexedDB with no list and no retry).
- The default deployment is unsafe (LAN address as origin, bind `0.0.0.0`,
  unauthenticated `/metrics`, consent-free OAuth authorize route).
- About 53,000 of 98,700 backend lines are removable without removing a
  shipped feature (dereferenced contract, dead multi-user code, dead SQL).

Fixing items one by one inside this structure does not converge. The plan
below first cuts the product to its definition, then rebuilds the three
surfaces that matter (editor, shell, save path) on one model each.

## 2. Product definition for v0.1

NotesApp is a self-hosted Markdown notes application for one person.

- Notes are Markdown files with one `.md` suffix, organised in folders. The
  file is the document. Nothing is stored that cannot be exported as plain
  Markdown files.
- One editing surface: a live-preview Markdown editor where the source stays
  editable at every position. A Read mode shows the same note rendered by the
  reference renderer.
- Typing writes a local draft on the device. Save creates one immutable
  version on the server. History lists versions and restores any of them.
- Works offline. A queued save is sent when the connection returns. The user
  sees one linear history and is told when a later save superseded an earlier
  one.
- Deleting moves a note to Trash. Trash restores or deletes permanently.
- Search finds notes by name and content, ranked, with a highlighted excerpt.
- Installs from one Compose file with safe defaults. Backup is a zip of
  Markdown files plus a database dump.

Not in v0.1: multiple workspaces in the interface, sharing, collaboration,
agent tokens, MCP servers, OAuth, metrics endpoint, write pause, named
checkpoints, wiki links and backlinks (see decision D4), public share pages,
tags, pinning, import (see D9).

### Quality bar

- The Markdown matrix in `docs/plans/003-audit/markdown-editor.md` shows
  "yes" for every CommonMark and GFM row in both columns, plus math and
  Mermaid.
- Every P0 journey has a browser test that runs in CI on every push to `main`.
- No raw identifier, ISO timestamp, error code or engine notice reaches the
  user.
- WCAG AA contrast on every rendered text pair in both palettes. Every dialog
  traps focus, closes on Escape and restores focus.
- Phone layout works at 390 px with no horizontal scroll, and every action is
  reachable by touch.
- Initial JavaScript under 256 KB gzip. Assets served compressed with cache
  and security headers.

## 3. Architecture decisions

These decisions are made. They are recorded here so that every agent that
works on an item applies the same model. Each one also has a decision record
in [docs/decisions](../decisions/README.md): D1 to D15 are records 0001 to 0015.

**D1. One Markdown grammar.** `packages/markdown` (remark, CommonMark plus
GFM, math, sanitizer, URL policy) is the only definition of the language. The
live preview in `packages/editor` is rebuilt on the Lezer Markdown syntax tree
that CodeMirror already parses (`syntaxTree(state)`), not on a second scanner.
The outline reads the same tree. One corpus document is rendered through both
paths in a test and the two outputs must agree on structure. The regular
expression scanner (`live-preview.ts` marker scanning, `widgets.ts` block
detection) is deleted.

**D2. Widgets only where text cannot express the result.** Images, Mermaid
diagrams and display math render as block widgets that cover whole lines, are
selection aware (the block opens as source when the cursor or selection
touches it) and are atomic for cursor movement. Tables stay as text with
alignment and column decorations so they remain editable in place. Inline math
renders inline with no chrome. Single-dollar math is disabled; inline math
uses `$$...$$` or `\(...\)`. Task boxes are real checkbox widgets that carry
their own position. Code fences get syntax highlighting and hide the fence
lines.

**D3. Read mode is the second consumer of the renderer.** The note screen gets
a Write and Read toggle. Read renders with `renderMarkdown` from
`packages/markdown`. This gives the renderer a real user and gives the user a
clean reading surface. The unused public share page is deleted.

**D4. Standard links between notes, no wiki syntax in v0.1.** `[[Title]]`
support is removed from the editor, the renderer policy and the index.
Linking to another note is a standard Markdown link to its path, with
autocompletion when the user types `](` or a `[[`-style trigger that inserts a
standard link. Backlinks and the link index return in v0.2 built on standard
links. Confirmed by decision Q2.

**D5. Workspace becomes an implicit container.** The server keeps the
`workspaceId` in the API and the URL. The interface removes the switcher,
create screen, settings screen, role badges, read-only states and viewer
notices. The single personal workspace is the only one.

**D6. Trash replaces purge.** Deleted notes are listed in Trash with Restore
and Delete permanently. The purge API stays and is called by Delete
permanently. The purge, recovery and offline-status screens are removed. Their
useful pieces move: offline availability into Settings, parked saves into a
Needs attention list reachable from the save state chip.

**D7. Keep the save model, close its gaps.** Draft, local version, queue entry
and server version stay separate. Changes: a draft that is older than the
accepted head is detected on open and the user chooses; a rebase that moved
the parent returns the superseded revision and the client shows a notice; a
rebase across a deletion or a rename boundary is refused with `stale_head` and
the client refreshes; folder rename becomes metadata only; a refused save is
written to the recovery area and listed; an unchanged Save is a no-op; the
message `Manual save` is no longer written.

**D8. Remove the remote integration surface for v0.1.** Remote MCP server,
OAuth authorization server, agent tokens, `apps/mcp-stdio`, the `/metrics`
route and the write pause are removed from the product. The code is deleted,
not flagged, because dead code is what caused the loop. MCP returns in v0.2 as
a stdio adapter with a manually issued token, on top of the same contract (decision Q1).

**D9. Export first, import later.** Export one note or all notes as `.md`
files in a zip is in v0.1. Import of `.md` files is v0.2 unless it proves
trivial after export lands.

**D10. One command palette.** `Cmd/Ctrl+K` opens one dialog that lists recent
notes, matches names first and content second, and offers actions (New note,
Toggle theme, Shortcuts, Open history, Toggle Read mode). The header search
dropdown and the `Cmd+O` quick open are removed. A search icon in the header
opens the same dialog at every width. `Cmd+O` stays as an alias.

**D11. Contract emit with shared definitions and one migration.** The
generated contract index uses one `$defs` block instead of 259 dereferenced
copies of the error schema. Validators are cached by schema digest. The eleven
migrations are squashed into one, which also removes the dead tables and
functions and the journal ordering defect. Squashing is allowed because no
installation holds real data (decision Q3).

**D12. Package layout stays for v0.1.** Dead code is deleted from every
package, but no package is merged in this release. The merges recommended in
the backend audit (`sync` plus `storage-browser`, the `api` trio, `editor`
into `ui`) are v0.2 work after the code is smaller.

**D13. Delivery and headers belong to the app.** The Fastify static handler
serves precompressed assets with `Cache-Control`, `ETag` and security headers
(CSP, `nosniff`, `Referrer-Policy`, frame rules). Source maps are hidden. The
service worker precaches the shell only; diagram chunks load on demand. The
diagram frame stays sandboxed; its scripts become a self-contained bundle so
the sandboxed origin can load them.

**D14. Browser tests are the interface gate.** No DOM unit framework is
added. Component logic that needs a unit test is extracted into pure modules,
as `save-state.ts` and `note-name.ts` already are. The Playwright matrix runs
on every push to `main`.

**D15. The note surface is the design.** Typography, measure and vertical
rhythm of the note are designed first. Chrome recedes: a 48 px header, a quiet
sidebar, one primary action. The palette stays Tokyo Night, exposed to the
user as System, Light and Dark. Layout primitives (Page, PageHeader, Card,
Dialog, EmptyState, ListRow) move into `packages/ui` and every screen uses
them.

## 5. Phases and sequencing

Each phase is executed by Opus agents in git worktrees, one short-lived branch
per item group, fast-forward merged to `main` after `pnpm verify` and the
relevant browser tests pass. The orchestrator reviews every change against
this document before it is merged.

**Phase 0. Stop the bleeding.** W1 P0 items and W2 P0 items. These touch the
save path and the deployment defaults and do not depend on any redesign. Exit:
no known data-loss path in single-user use; a fresh `docker compose up` is
safe on a public host.

**Phase 1. Cut to the definition.** D5, D6, D8: remove MCP, OAuth, agent
tokens, metrics, write pause, workspace UI, purge, recovery and offline-status
screens, wiki links, named checkpoints. Delete dead multi-user
code, tests and SQL. Squash migrations (D11). Contract emit with `$defs`.
Exit: the code base describes only the v0.1 product; `pnpm verify` and the
browser matrix pass; backend line count drops by about half.

**Phase 2. Editor rebuild.** W4. Runs in `packages/editor` and
`packages/markdown` with the equivalence corpus test as the gate. Read mode.
Exit: the Markdown matrix is all "yes"; rich blocks are editable; formatting
and find work; Mermaid and math render.

**Phase 3. Shell and screens.** W5. Runs in `apps/web` and `packages/ui` in
parallel with Phase 2, coordinated through the note screen contract: the
editor package exposes one `createNoteEditor` surface and the shell owns
everything around it. Exit: the screen inventory matches section 2; the
accessibility and phone bars are met.

**Phase 4. Data and API.** W3 P1 items and the W2 P1 items not done in
Phase 0. Created timestamp, sort, search quality, export, delivery headers.
Runs in parallel with Phases 2 and 3; the shell consumes the new operations
when they land.

**Phase 5. Release engineering.** W6. CI browser matrix starts in Phase 0 and
runs on every later push to `main`. Docs, hygiene, changelog and tag at the end.

Parallelism: Phase 0 is one stream. Phase 1 is two streams (backend cut,
frontend cut). Phases 2, 3 and 4 are three streams. Phase 5 runs alongside
with one stream.

## 7. Product owner decisions

Decided on 2026-09-10.

- **Q1. MCP in v0.1.** Decision: remove all of it now (remote server, OAuth,
  agent tokens, `apps/mcp-stdio`). A stdio adapter returns in v0.2.
- **Q2. Wiki links and backlinks.** Decision: remove `[[...]]` and backlinks
  from v0.1. Notes link with standard Markdown links plus path completion.
- **Q3. Migration squash.** Decision: squash to one migration. No installation
  holds real data.
- **Q4. Public release.** Assumed yes: the repository becomes public at v0.1.
- **Q5. Folders.** Assumed: keep path-based folders with New folder, Move to
  and Rename.
- **Q6. Branch workflow.** Decision: commit directly to `main`. Agents work in
  a worktree on a short-lived branch, run `pnpm verify` and the relevant
  browser tests, rebase onto `main`, fast-forward merge, and delete the
  branch. No pull requests. `AGENTS.md` is corrected to say this.
- **Q7. Named checkpoints.** Assumed: dropped for v0.1.

## 8. Definition of done for v0.1

- Every P0 and P1 item in section 4 is merged, or moved to the v0.2 list with
  a written reason.
- The five audit reports are re-run against the release commit and no P0 or
  P1 remains.
- `pnpm verify`, the browser matrix, the bundle budget and the image build
  pass in CI on the release commit.
- A fresh `docker compose up` on a clean machine reaches the setup screen with
  the documented five commands, and the quickstart is followed once by someone
  who did not write it.
- `CHANGELOG.md` has a `0.1.0` entry and the commit is tagged `v0.1.0`.
